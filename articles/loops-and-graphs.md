你检查 agent 走的每一步。你是唯一在查的人，不管你乐不乐意。

要从这把椅子上站起来，需要两样东西，而几乎所有人只建了其中一样。

循环让一个工作单元不用你参与就是正确的。图决定到底存在哪些单元。

下面是这条分界线、那些不显眼的机制，以及你从「批准一切」走到「只批准一件事」的那个点。

## 循环是一个能失败的检查

把其他一切都剥掉，循环就四个部分：产出，检查，纠正，重复直到变绿。

检查就是全部。

没有一个你不在场时能否决工作的机制，你手里就没有循环，只有一个调度器。

这听起来是句废话，但几乎没有人先把检查写出来。

他们先建工作本身，再往末端拧一个 review，而这个 review 不过是叫另一个模型看一眼输出。

两个乐观主义者互相点头。

**先把条件写出来，而且要写成程序能执行判定的形式：**

```text
GREEN         测试套件退出码为 0
GREEN         每条论断都带来源行
GREEN         diff 只碰计划里列出的文件
```

```text
NOT A CHECK   输出看起来不错
NOT A CHECK   模型说它有信心
NOT A CHECK   没有报错
```

最后一条最容易让细心的人中招。没有报错不是正确的证据。

在这上面建循环，你会得到一个满怀自信重复同一个错误的系统，一路日志干干净净，直到预算烧完。

## 没人提醒你的天花板

循环让一个工作单元变得更好。这就是它全部的职责，而且它干得非常好。

它决定不了存在哪些单元、先后顺序如何，也注意不到五个步骤里有两个从头到尾不必互相等。

于是你得到一个非常强的 agent，在用错误的顺序、一次一个地跑错误的那三步。

每一步都对，结果照样又慢又走形。调循环救不了它，因为毛病不在任何单元内部。

就在这个时刻，人们开始怪模型。也是在这个时刻，下一层开始回本。

## 图是上面那层

**图是工作的形状：**什么在跑，什么同时在跑，什么在等，什么根本不该跑，结果从哪里回流。

只有两种东西，没有别的。节点是一个工作单元：一件有边界的活，一个输入进，一个输出出。

边是一个依赖：这个节点的输出喂给那个节点的输入。

每一次不必要的等待背后，都是同一个错误：把「然后」当成了边。

「总结这个文件，然后查天气」，这两件事之间没有边。天气不消费摘要。

它们是两个独立的节点，是一条线性脚本把它们串了起来，而串联的依据不过是你敲字的先后顺序。

**拿这个办法过一遍你现有流水线里的每一条箭头：**下一步真的读上一步的输出吗？

说不出跨过去的是哪个变量，就没有边，那份等待纯属浪费。

大多数链路里有两三条这样的箭头，找出它们通常是能拿到的最大单项提速。

## 四种节点，其中一种不是模型

拆分器、工人、代码节点，外加一道门。全部词汇就这些。

拆分器把工作切成单元，坐在最前面。

它做的决定比任何其他节点都多，因为按错误的维度切，下游全部作废。

按文件夹切一个仓库，四个工人会审计同样的三个文件。

按爆炸半径切，每个人都能看到别人看不到的东西。

工人每人一个单元，一副镜片，一段自己的上下文。最后那一条最常被人跳过。

给四个审计员一扇共享窗口，他们就会趋同：第一个写下一处发现，其余的人读到它，四份报告全都围着同一件事打转。

**你付了四份钱，买到一份观点和三声回声。**

代码节点是大家忘了它存在的那种。合并、排序，把重复的去掉，再比较每一份导出改动前后的差异。

这些没有一样是推理。每一件都有唯一正确的答案，每一件都只有几行代码，而让模型来跑，是给一个本来没有成本的步骤加上成本、延迟和方差。

描述这个变换时用不着判断、决定这类词，也用不着评估或总结，它就是代码。

一张每条边都是 agent 的图，是在为自己的接线付租金。

![词汇表「Four kinds of node, and one of them is not a model」：SPLITTER（MODEL 徽章）切分工作，全图一个，在最前端；WORKER（MODEL）一个单元一副镜片一段上下文，构成并行车道；CODE NODE（CODE）合并、排序、去重、比较，零 token、确定性；GATE（EITHER）检查并能把工作打回，没有它就只有流水线。底部统计：每图 1 个拆分器、3 到 6 条车道、代码节点 0 token、最少 1 道门](/sdlc-playbook/articles/loops-and-graphs/four-nodes.png)

## 循环到底住在哪

一句话解开全部困惑：循环住在节点里面，图住在节点之间。

**在一个单元内部：**产出，检查，纠正，重复直到变绿。

**在单元之间：**拆分，扇出，合并，设门，退回。第二张清单里的每一项，都无法从单个单元内部表达出来。

所以两者不用选。节点里没有循环的图，会并行产出未经验证的工作，比串行更糟，因为量更大了。

没有图包在外面的循环，就是一个非常好的步骤，排在一条没人设计过的队列里。

## 两条回流路径，以及人人都跳过的那一条

没有回头路的图就是一条流水线。它产出结果，然后忘掉。

下周它从同一个起点重来，带着同一批盲区。

能用的图有两条回流路径，干的活不一样。

纠正边是短的。门把一个单元打回产出它的那一步，修好的是你正在跑的这一轮。

学习边是长的。一个被接受的结果化作约束回到拆分器，修好的是之后的每一轮。

几乎人人建了第一条、跳过第二条。特征就是一个系统跑得很快，却从不变聪明。

**学习边不搬输出。它搬的是从输出推导出的约束：**

```text
ACCEPTED   utils 切片移植完成，一次通过
DERIVED    适配器必须原样保留关键字参数
LANDS IN   拆分器之后每一个切片的任务书
```

注意它落在哪里。不进工人的指令，进的是拆分器的任务书，那份任务书决定工作怎么切。

一个被确认的原因变成一条规则，下一次断裂就从这一次的终点开始。

![两条回流路径图「TWO RETURN PATHS」：splitter → workers → merge → gate → result 的横向流程。红色短虚线从 gate 弯回 workers，是纠正边，修好当前这一轮；紫色长实线从 result 弯回 splitter，是学习边，修好之后的每一轮。下方白板列出长边搬运的东西：ACCEPTED 一条、DERIVED 一条，落进拆分器之后每个切片的任务书](/sdlc-playbook/articles/loops-and-graphs/return-paths.png)

## 退回单元，别退回整批

这是回流路径上最贵的错误，值得直说。

四个切片移植完毕，一个没过测试。整批退回的话，三个正确的切片会被重写。

它们的下一版只会不同，不会更好，因为它们本来就没毛病。

现在四个全部要重新验证，而那三个里随便哪个都可能因为不相干的原因在这轮失败。

你把一次失败换成了四个不确定的结果，还为此付了钱。一轮里干两次，系统就永远收敛不了。

从外面看，这像模型在反复失败。实际毁掉正确工作的，是回流路径。

**一次退回带着四样东西，每一样都在干活：**

```text
UNIT      handlers 切片
VERDICT   red
REASON    test_auth_redirect 失败
EVIDENCE  期望 302，得到 200，handlers/auth.py:88
SCOPE     只修这个文件，不碰其他切片
```

SCOPE 这一行比看上去重要。

**没有它，被退回的单元会越长越大：**agent 打开文件，注意到旁边两个问题，顺手也修了，你的一次单切片纠正就变成了一个没人审过的四文件 diff。

上限设三次。一个单元三次纠正都失败，问题就出在产出它的那份计划里，而循环看不见计划。

## 门按爆炸半径开，不按置信度开

多数文章的做法是造一个置信度分数，设一道阈值，高于它的放行。这个变量选错了。

置信度是这个决策里最弱的输入。这一点容易漏掉，因为它是模型唯一能施加影响的输入。

强变量是改错了会发生什么。按撤销错误的代价给工作分道：

可逆且影响可控。一处文案改动、一个测试，或者一个有覆盖率罩着的孤立函数。一次坏合并的代价不过是一次 revert，这条道可以最先开。

可逆但面宽。共享工具库、schema 新增，任何被十几个调用方摸到的东西。用确定性检查加一段干净的轨迹来设门。

难以逆转。迁移、删除，任何写生产数据或动钱的操作。这条道不开，分数再高也不开。

第三行与「阈值设得极高」是两回事：那是一条不开的道。这个区别要紧，因为阈值会被往下调，关掉的道不会。

**在开着的道里，门按顺序读证据：**先读确定性结果，再读这一轮的轨迹，然后读这个节点的工作以前被回滚的频率，模型自己的评估放在最后。

![分道图「Gate on blast radius, not on confidence」：三块面板从上到下。绿色「可逆且影响可控 · 最先开」，例：文案、测试、孤立函数，一次坏合并的代价是一次 revert；琥珀色「可逆但面宽 · 凭证据开」，例：共享工具、schema 新增，靠确定性检查加干净轨迹；鲑红色「难以逆转 · 保持关闭」，例：迁移、删除、动钱的操作，分数再高也不开。底部一行证据顺序：确定性 · 轨迹 · 回滚历史 · 模型自述放最后](/sdlc-playbook/articles/loops-and-graphs/gates.jpg)

## 从你自己的工作哪里下手

挑一件你反复做的事。画出拆分器，画出各条道，再画出合并、一道门和一条回边。

先建门。有东西能大声失败之后，一切都变容易。没有门的图，只是一种更快产出未验证结果的方式。

然后是道。最后才是学习边，因为在有东西接受结果之前，你没法从被接受的结果里推导约束。

把人放在一个步骤上，放在后果最重、可逆性最低的那个点。

批准合并。决定哪些修复上线。不看中间产物，不逐步确认。

放在图中间的人会成为图里最慢的节点，整张图的速度就是一个人读东西的速度。
