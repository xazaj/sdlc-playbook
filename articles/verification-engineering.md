你的 agent 说「做完了」。

你还是打开了它，而且打开是对的：按钮点不动，有一个数字不知从哪来，它引以为傲的那条测试什么也没测。

于是它做的每件事你现在都要亲自检查，等于 agent 什么也没替你省下。

当下 AI agent 真正的天花板是你还得读多少它的产出，能做多少从来不是卡点。

SpaceXAI 工程师 Lauren Tan 关于运行 agent 的演讲，开场就是这句话：「一切归根结底，是你对这个 bot 有多少信任。」

Claude Code 的创造者 Boris Cherny 把解法说成了一句：给模型一种验证自己工作的方式，产出质量能提升 2 到 3 倍。

这就是验证工程（Verification Engineering）。把检查建一次，从此你不再是那道检查。

前天讲的是 harness，单个 agent 周围的一切；昨天讲的是图，工作怎么在 agent 之间流动；今天讲的是你怎么知道这活真的做对了。

整套想法都收在这一篇里：

- 为什么 agent 的一句「做完了」本身什么都不能说明
- 「完成」的 6 个层级，以及大多数 agent 停在哪一级
- 一条可信任的检查由哪 5 个部分组成
- 为什么干活的 agent 永远不能给自己打分
- 一个错误一条规则：检查如何随时间自己长出来
- 一个实际例子，从 40 分钟的人工阅读降到 4 分钟
- 怎么判断自己缺的是哪条检查

## 30 秒版

如果只读一段，就读这段：

1. 「做完了」是一句主张，检查才是证明。没有证明，永远不接受主张。
2. 在开工之前把「好」写成一行行能通过或失败的标准。
3. 干活的 agent 永远不给自己打分；打分的是另一个 checker，它的默认答案是否。
4. 查结果，不查推理：跑起来、打开、点一遍，再重算一遍。
5. 你亲手抓到的每个错误都变成一条写下来的检查，同一个错误绝不抓第二次。

## 为什么「做完了」什么都不能说明

**agent 给自己打分时下手很轻**

Anthropic 在 2026 年 3 月的 harness 设计文章里写得很直白：让 agent 评估自己产出的工作，它倾向于自信地夸它，哪怕人一眼就能看出质量平庸。

他们的修法是给工作另配一个独立的评估器，并把它调校成怀疑姿态；让模型对自己的工作苛刻起来，他们发现那要难得多。

**它们查的是自己写的，没查你要的**

写完代码又自己写测试的 agent，测的一定是它写的那些代码，一个错误的想法每次都能通过它自己的测试。

**它们会钻检查的空子**

Anthropic 给 Claude 3.7 Sonnet 的系统卡里描述过：模型走捷径给测试开特例让它们通过，真正的问题留着不修。

给 agent 一条它能改的检查，它有时就会改那条检查。

这些都不说明 agent 不行，只说明「做完了」是一句主张，而主张需要证明。

## 「完成」的 6 个层级

每一份 agent 产出都落在这几级中的某一级，到第 4 级你才有资格不再逐字读。

**第 0 级：它这么说**

「做完了，都能跑」，没有任何证明。大多数 agent 就停在这里。

**第 1 级：它能跑**

构建通过、脚本跑完，文件也打得开。成本低，但只能抓住最蠢的失败。

**第 2 级：通过别人写的检查**

测试、schema、字数要求，加上一份必含章节清单，这些在开工前写好，且永远不出自干活的那只 agent。

**第 3 级：有人测过真实结果**

有个 checker 把上线页面点一遍，打开每个链接，从源头重算每个数字，再把测试邮件发给自己。

Anthropic 的评估器干的就是这个：用 Playwright 像真人用户那样开跑真实应用。

**第 4 级：证明随件附上**

每次说「做完了」都带上证明它的东西：截图、测试日志、链接，还有前后对比。你几秒钟核完证明，不必重做一遍工作。

**第 5 级：你只看不可撤销的事**

一切可逆的东西凭检查直接放行，你只审批发送、付款、删除，以及任何公开动作。

从 0 级到 3 级，改变的是你这一周；从 3 级到 4 级，改变的是你的信任。

## 一条可信任的检查的 5 个部分

**1. 标准先于工作写好**

别写「把它做好」，要写成一行行能通过或失败的标准：「每个数字都链到来源」「表单在手机上能提交」「全文 300 字以内」。

写不出标准，就说明这个任务还没到交给 agent 的时候。

**2. checker 与制作者分离**

一个独立的 agent，一份独立的上下文。它从不知道这活是怎么做出来的，只看工作和标准。

**3. 拿 ground truth，别靠读**

Anthropic 的《Building effective agents》指南讲的是同一件事：agent 每一步都需要来自环境的 ground truth，工具调用的结果、代码的输出。

读一遍代码说它看起来没问题，这不过是加了步骤的第 0 级。跑起来。

**4. 默认答案是否**

checker 只在每条标准都通过时才放行，否则连同失败的那几行原文一起打回。

**5. 每次通过都附证明**

没有证明的通过只是又一句主张，所以 checker 会把它看到的东西附上。

## 干活的永远不给自己打分

如果整篇只能留一条规则，我留这条。

制作者知道自己每个选择背后的理由，所以每个选择在它眼里都是对的。

checker 只知道你要什么、它看见什么，所以能找出两者之间的差距。

三样东西保证 checker 不作假：

- 它永远拿不到制作者的推理，只有结果和标准
- 它改不了工作也改不了检查，只能放行或打回
- 它测的是跑起来的真实结果，绝不测「理应产出这结果」的代码

两者之间的循环有上限：3 轮，之后停下问你。

## 一个错误一条规则

Lauren Tan 运行 agent 的方式归结起来就是这一条：每个错误写一条规则，只写一次，从此不再手工纠正。

她展示过自己每月合并的 PR 从 809 涨到 10,926。agent 没变聪明，变长的是检查清单。

习惯本身很简单：

1. 你手工抓到一个问题
2. 别在对话里顺手修掉，去写下那条本可以抓住它的检查
3. 它进 CHECKS.md，从此 checker 对每个任务逐行执行

第一周你抓 10 个问题，第四周抓 1 个，另外 9 个已经变成检查了。

## 一个实际例子：每周客户报告

**之前**

每周五，一个 agent 从销售表和投放 dashboard 里取数，写一份 4 页的报告。

它永远说「做完了」，我还是把 4 页全读一遍，大约 40 分钟，因为出过两次数字错误、一次链接指错了客户。

**之后**

agent 写报告 → checker 跑 CHECKS.md → 失败项连同失败行打回，最多 3 轮 → 我读结论、批准发送。

checker 从表格重算每个数字，打开每个链接，把本周与上周对比，标记任何超过 30% 的变化。

我现在读的是一行「7 项检查全部通过」，外加 2 条带来源的标记变化，大约 4 分钟。

**那个文件：CHECKS.md**

checker 在每个任务前读它，制作者永远看不到自己是怎么被打分的：

> TASK：每周客户报告，周五上午 10 点发送
> PASS ONLY IF：下列检查全部通过，否则连同失败行打回
> 1. 每个数字与表格一致，重算得出，禁止照抄
> 2. 每个链接都能打开，且属于这位客户
> 3. 与上周相比任何超过 30% 的变化，都带来源标记
> 4. 任何位置不得出现除本客户以外的客户名
> 5. 600 字以内，3 个必含章节齐全
> 6. 每个日期都来自本周，不得沿用上周
> 7. 附上：所用表格范围、每个已核链接、与上周的 diff
> LIMIT：3 轮，之后停下问我
> NEVER：未经我批准，任何东西不得发给客户

第 4 条和第 6 条第一周时还没有，它们是我手工抓到的两个错误，各抓了一次。

## 你缺的是哪条检查

你还是不敢信任一个 agent，症状会告诉你缺了哪条检查：

- 它说做完了、其实没有 → 开工前没写标准
- 测试全绿、东西是坏的 → 制作者自己写了测试
- 看着对、数字是错的 → 没人从源头重算过
- agent 那边能用、你这边不行 → checker 读了代码，没用结果
- 同一个错误每周都回来 → 修在了对话里，没进 CHECKS.md
- 你还是每样都读 → 通过时没附证明

六种症状，六条缺失的检查，没有一条是靠更聪明的模型修好的。

## 让验证失效的错误做法

**问 agent「你确定吗？」**

犯错的还是那个上下文，所以它说确定，或者道个歉，把本来对的东西改了。

**标准含糊**

「确保高质量」这种标准什么都能通过。

**checker 有编辑权**

它一旦能修东西，就不报东西了。

**只在最后查一次**

错误的计划等建完 2 小时后才被查出来，就浪费了 2 小时。先查计划。

**让 checker 读推理过程**

一个好故事能让烂活看着没事。

**循环没有上限**

3 轮，然后交给人。

**永远事事亲查**

抓到第二次，它就该是一条检查，不该再靠习惯。

## 今晚从哪开始

1. 挑出那个你总要复查的 agent 任务
2. 把你检查时真正在看的东西写下来，那就是你的第一份 CHECKS.md
3. 让第二个 agent 当 checker：只给标准和结果，默认答案是否，附证明
4. 下个任务跑起来，只读结论和证明
5. 每次抓到它漏掉的，加一行

然后留意你一周里有多少时间，原本花在读那些其实已经对了的工作上。

P.S. 还得检查的 agent 省不下你的时间，只是把时间挪了个位置。
