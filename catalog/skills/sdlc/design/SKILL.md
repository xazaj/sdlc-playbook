# 设计方案选型

读取决策矩阵，针对用户手上这个界面给出**一个**建议。

**决策矩阵：** `~/.sdlc/stages/20-design/DECIDE.md`（`~` 为当前用户家目录）

## 用法

0. 先跑 `~/.sdlc/bin/check-update.sh`。它平时静默，只在知识库落后于远端时输出一行 —— 有输出就转告用户，然后继续。已节流，不会每次都发网络请求。
1. 若以下几点未知，先问清楚（一次一个）：这个界面要活多久？大概几屏？需要品牌辨识度吗？
2. 读上面的 DECIDE.md，按"判断依据"和"推荐路径"两节定位。
3. 给出一个明确建议并说明理由，**不要罗列全部方案让用户自己挑**。
4. 若这个界面要交给 agent 生成，必须读"交给 agent 执行时的差异"一节 —— 那里讲的是怎么避免模板感。

本技能只管**选方案**。选定之后的具体视觉实现，交给 frontend-design 一类的实现技能。

不要把 DECIDE.md 整篇复述出来。
