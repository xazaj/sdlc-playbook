# 需求与规格选型

读取决策矩阵，针对用户当前的具体需求给出一个建议。

决策矩阵：`~/.sdlc/stages/15-define/DECIDE.md`（`~` 为当前用户家目录）

## 用法

0. 执行 `~/.sdlc/bin/check-update.sh`。脚本已节流，最新时静默；若有输出，转告用户后继续。
1. 以下三项若未知，先向用户确认，每次只问一项：这个需求有几个人要看过并认同？需求现在说得清目的与成功标准吗？会交给 agent 长时间自主执行吗？
2. 读取 DECIDE.md，依据「判断依据」与「推荐路径」两节定位规格形态（口头确认、EARS 条目、PRD、变更级规格）。
3. 给出一个明确建议并说明理由，指向对应的登记卡。不罗列全部选项让用户自行挑选。
4. 若问的是「这次改动要不要先写规格、要不要先写测试」，改走 `~/.sdlc/stages/30-coding/DECIDE.md`，那是开发流程判定；本矩阵只管写到多细、按什么句式、谁来审。

不复述 DECIDE.md 全文。
