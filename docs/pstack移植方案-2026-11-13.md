# pstack 移植方案：Rulestack 项目，pi 与 Codex 双端

> 日期：2026-11-13。状态：**已落地并验证**。本文记录移植的完整决策链，供后续给其他项目复用或维护 Rulestack 的移植时查阅。落地资产在 Rulestack 仓库：`vendor/pstack/`、`pstack-port/`（commit `72bf4502..5f9523ba`）。

## 一、背景与目标

[pstack](https://github.com/cursor/plugins/tree/main/pstack)（Lauren Tan，Cursor 团队）是 cursor/plugins 仓库中最大的 agent 工程纪律技能集：57 个技能、23 个 playbook、24 条原则，入口是 `poteto-mode` 路由技能。它的价值不在某个单点功能，而在把「写得少但写得好」的判断纪律编码成可复用规则：证明而非自述（prove-it-works）、找根因（fix-root-causes）、对抗审查只留被运行证实的发现（interrogate）、先删后加（subtract-before-you-add）。

pstack 原生运行在 Cursor 上，重度依赖 Cursor 的 Task 子代理、模型路由（`~/.cursor/rules/pstack-models.mdc`）和若干 Cursor 内建（`/loop`、Bugbot、Automations）。目标：让它在 **pi** 与 **Codex**（本机 `codex-cli 0.169.0`）上都真实生效——不是降级到「只读原则」，而是保留并行 fan-out、跨模型交叉评审、worktree 隔离这些核心机制（全保真口径）。

## 二、可行性结论（为什么这条路走得通）

三个事实决定了方案形态：

1. **三端技能格式同源**。pi 实现了 [Agent Skills 规范](https://agentskills.io)，Codex 官方文档明确从 `$REPO_ROOT/.agents/skills` 递归发现技能且**支持 symlink**；pi 的技能加载器（`dist/core/skills.js`）对 `entry.isSymbolicLink()` 有显式的 `statSync` 跟随处理。pstack 的 SKILL.md 就是这个规范——格式层零改动。
2. **pstack 本体无 hooks、无 MCP**。它是纯 `skills/` + `agents/`（子代理 brief 文本）。真正依赖 Cursor 运行时的部分（Task 工具、模型 slug、内建命令）全部可以靠「映射文档」转译——上游自己就是这么移植到 Claude Code 的（`docs/harness/claude-code.md` 是一张 Cursor 名→Claude Code 名的映射表，读一次/session）。给 pi 和 Codex 各写一张同构的表即可。
3. **本机已有子代理底座**。pi 侧有 `~/tools/pi-call/`（pi-task 后台任务库：`--model` 锁模型、`--no-write` 只读、`reply` 续会话、TASK id 轮询）；Codex 侧有 `codex exec`（`-C` 指定目录、`-m` 锁模型、`--sandbox read-only`）。并行 fan-out = 多进程 + git worktree，等价于上游 `environment: "cloud"` 的 Claude Code 映射。

## 三、布局与决策

```
Rulestack/
├── vendor/pstack/               # 上游原样快照（进 git，pin commit）
│   ├── PROVENANCE.md            # 来源、commit、范围、同步五步
│   ├── pstack/                  # skills/ + agents/ + docs/guide/ + README + plugin.json
│   └── cursor-team-kit/skills/  # deslop / control-cli / control-ui / verify-this
├── pstack-port/                 # 适配层（进 git）
│   ├── harness/pi.md            # pi 映射表
│   ├── harness/codex.md         # Codex 映射表
│   ├── pstack-models.md         # 模型路由（取代上游 pstack-models.mdc）
│   ├── scripts/mount.sh         # 幂等生成 .agents/skills/ symlink（62 个）
│   └── README.md                # 入口：用法、验证、裁剪、附录 AGENTS.md 节模板
└── .agents/skills/<name>        # symlink 挂载点（本机视图，gitignore）
```

五个关键决策，每个都有备选和取舍理由：

**D1 单一事实源 = vendor，挂载 = symlink。** `.agents/skills/<name>` 是指向 `vendor/pstack/pstack/skills/<name>` 的相对 symlink。pi 与 Codex 共用同一个发现位，上游更新只重 vendor、重挂载，适配层不合并任何上游文本。备选「拷贝两份到两端目录」被否：漂移风险 × 2。

**D2 vendor 一字不改，适配全外置在映射文档。** 沿用上游官方 Claude Code 适配的同一模式：技能正文引用 Cursor 名，harness 文档负责翻译（`Task` → `pi-task run` / `codex exec`；`~/.cursor/rules/pstack-models.mdc` → `pstack-port/pstack-models.md`；transcript 路径 → 各端会话目录）。技能里「`~/.cursor/plugins/` 搜索 poteto-mode」这类路径指令，在映射表的 subagent 行明确改写为 vendor 绝对路径。

**D3 `.agents/skills/` 遵守宿主项目的本机化惯例。** Rulestack 的 `.gitignore` 整体忽略 `.agents/` 与 `AGENTS.md`（技能挂载与 AGENTS 均为机器本地资产，第 94/97 行），symlink 不入库；跨机器重建走两步：`mount.sh` + 从 `pstack-port/README.md` 附录抄 AGENTS.md 节。这与宿主已有先例（modern-web-guidance 的安装注释，第 110-113 行）一致。

**D4 Cursor-only 功能跳过，不模拟。** Bugbot、Automations（benny 整包）、Cursor 云代理、`/loop`：按上游先例输出一行 `Skipped on <harness>: <step>. <reason>.` 继续执行。审查过 poteto-mode 全部触发器：主流程不依赖这些。

**D5 跨模型交叉评审靠「互借进程」满足。** 上游要求 cross-judge 不得与 parent 同模型家族。pi 会话的 judge 借 Codex（`codex exec -m gpt-6.1-sol --sandbox read-only`）；Codex 会话的 judge 借 pi（`pi-run --model auto/glm-5.3 --no-write`）。两端互为对方的异家族第二意见，这恰好也是 advisor 插件「跨模型第二意见」思想的落地。

**模型路由表**（`pstack-port/pstack-models.md`）按角色映射：pi 经 magpie 路由（`auto/glm-5.3` 强档 / `zai/glm-5.3-flash` 快档 / `deepseek/deepseek-flash`），Codex 单家族 `gpt-6.1-sol` 靠 `model_reasoning_effort` 分档。拒绝降级链：同族最近档 → 跨 harness 借席 → drop seat 并说明。

**兄弟技能摘取**：poteto-mode 运行时引用 cursor-team-kit 的 `deslop`（commit 前）、`control-cli`/`control-ui`（验证 CLI/UI）。只 vendor 这四个，thermos 未启用（引用处按跳过处理），避免全家桶化。

## 四、宿主项目门禁的应对

Rulestack 有三条与本移植相交的治理规则，处理方式：

1. **workspace-layout guard**：根目录新增项必须在 `scripts/guard-workspace-layout.mjs` 的 `ALLOWED_DIRS` 登记并写理由。已按 guard 自己给出的正规路径加 `vendor`、`pstack-port` 两行（理由注释在脚本内）。
2. **提交门禁**：`pnpm typecheck` 全清（跑过，apps 全 Done）+ 暂存文件 eslint（guard 脚本改过后单独 lint 通过）。移植只新增 md 与一个 bash 脚本，不触产品代码。
3. **按路径暂存、Conventional Commits**：分三个 commit——`chore(guard)`（白名单）、`chore(vendor)`（上游快照）、`docs(pstack)`（适配层）。未推送（Rulestack 的推送由门禁机跑 CI，留给用户决定何时推）。

## 五、验证结果（2026-11-13 本机实测）

| 验证 | 命令 | 结果 |
|---|---|---|
| 挂载 | `bash pstack-port/scripts/mount.sh` | mounted=62（57 pstack + 4 team-kit + 计数含 poteto-help 等），幂等重跑 skipped=62 |
| pi 发现 | `pi-run <repo> "list skills starting with poteto/principle-"` | 列出 `control-cli`、`deslop`、`setup-pstack`、`verify-this` 等；`poteto-mode`/`principle-*` 不在广播列表——**预期行为**，它们带 `disable-model-invocation: true`，pi 从自动列表隐藏，经 `/skill:poteto-mode` 显式触发或按文件路径读取（poteto-mode 的设计本就靠读 `../<name>/SKILL.md` 路由，不依赖广播） |
| Codex 发现 | `codex exec --sandbox read-only "names of skills starting with poteto"` | `poteto-mode` + 全部 24 条 `principle-*` 列出 ✓ |
| 门禁 | guard / typecheck / eslint | 全过 |

双端差异记录在 `pstack-port/README.md`：Codex 技能列表有上下文预算（默认 2%，可 `skills.max_context_tokens` 调到 10000），全量挂载可能触发截断警告；pi 侧约 8KB 常驻。裁剪方法：删 symlink 不影响 poteto-mode 的相对路径路由。

## 六、维护与复用

- **更新**：`vendor/pstack/PROVENANCE.md` 的五步同步流程（换 commit 重 vendor → 核对 poteto-mode 互引约定 → 更新 PROVENANCE → 重挂载 → 冒烟）。上游 0.15.x 迭代快，建议跟随而非自动。
- **复用到其他项目**：本方案的模板资产是 `pstack-port/` 四个文件（两张映射表可原样搬，models 表按目标机器改）。若要给多个项目装，值得把「vendor + port + mount」提炼成安装脚本，但按 SDLC 当前阶段的纪律，等第二个真实项目需要时再做。
- **与 SDLC 目录的关系**：pstack 暂不登记进 `registry/`——它是被移植后定制的资产，不是「现成够用」的原样资产；若未来上游出现官方多 harness 版本，再评估登记卡。

## 七、遗留与边界

1. **未做端到端实战验证**：冒烟只验证了「技能被发现」，还没在 pi/Codex 里跑一次完整 `poteto-mode` 任务（含 pi-task/codex exec fan-out）。首次实战时注意观察：agent 是否真的先读 harness 映射表、subagent brief 是否按表拼接。
2. **`/loop` 无人值守循环**是映射而非等价物：bash 循环调子进程与 Cursor 原生 loop 的会话连续性不同，长任务优先用 pi-task 的任务库模式。
3. **Codex 的 `resume`**：无可靠跨进程续话，映射为「重 spawn + brief 粘贴先前结果」（上游 Claude Code 适配同款保守处理）。
4. **AGENTS.md 节只在本机生效**：其他协作者的机器需各自跑 mount.sh 并抄节（README 附录已含模板）。这是宿主项目本机化哲学的结果，不是缺陷。
