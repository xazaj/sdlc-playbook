# SDLC Playbook v2：GitHub Pages 站点规划

- 日期：2026-09-03
- 状态：暂缓（2026-09-03 评审）。重启条件：条目数达到六个以上，且有仓库以外的访问来源
- 依赖：`2026-09-03-playbook-v2-catalog-design.md`（条目格式与目录结构，已部分采纳）
- 修订：v2 方案第 7 节"不做文档站"改为"做，但由 markdown 生成"

## 1. 结论

建一套由 markdown 自动生成的静态站，不手写 HTML。

条目的唯一真源是分类目录下的 `.md`。若另写一套 HTML，就有两份内容需要同步，几周内必然漂移，而"保证最新"正是本库的核心承诺。HTML 必须是 md 的渲染结果，不能是第二份手稿。

生成器选用 Jekyll，理由如下：

- GitHub Pages 原生支持，在仓库设置中选择 main 分支即上线，零 CI 配置，零依赖安装。
- 它读取的正是已定的 frontmatter，`evaluated_version`、`evaluated_at`、`category`、`agents` 可直接用于列表、筛选与徽标。
- 布局、样式、脚本全部自写，不用主题，设计不受限。
- 贡献者只接触 md，永远不需要接触站点代码。

否决的方案：

| 方案 | 否决原因 |
|---|---|
| 手写一套 HTML | 两份真源，必然漂移 |
| 单页 HTML 运行时拉取 raw md 渲染 | 需要一份条目清单文件或调用 GitHub API。前者又是第二真源，后者有速率限制；且依赖 CDN 与 JS，无 SEO |
| Astro / VitePress | 需要 Node 依赖与构建配置，对"只想改一个 md"的贡献者是负担；设计自由度并不高于自写 Jekyll 布局 |

Jekyll 的已知限制及对策：GitHub Pages 内置的 Jekyll 版本较旧，且不允许第三方插件。本站只用内置的 Liquid 与 kramdown，不需要插件。若将来需要，改为在 GitHub Actions 中执行 `jekyll build` 再部署，源文件不变。

## 2. 站点信息架构

三层：首页、分类页、条目页。

### 2.1 首页 `/`

- 一句话定位与三步用法：翻、复制、贴。
- 三个分类卡片：设计系统、开发工作流、Skill，各带条目数与一句话说明。
- 全站搜索框，客户端实现，见第 4 节。
- "最近更新"：按 `evaluated_at` 倒序取 6 条。
- "需复核"：`evaluated_at` 超过 180 天的条目。有则显示，无则整块不出现。

### 2.2 分类页 `/design-systems/`、`/workflows/`、`/skills/`

- 顶部：该分类的"怎么选"，即 v1 DECIDE.md 压缩后的内容，来自分类目录 `README.md` 的正文。
- 下方：条目卡片列表。每张卡片显示名称、一句话、评估版本、评估日期、新鲜度徽标、来源（自建或外部）、支持的 agent。
- 筛选条：来源、agent、新鲜度。客户端筛选，不刷新页面。

### 2.3 条目页 `/workflows/tdd-superpowers/`

- 页头：名称、一句话、元数据条（评估版本、评估日期、新鲜度徽标、上游链接、agent 支持）。
- 正文六节按 v2 格式渲染。
- 安装 prompt 块是页面重心：等宽字体、独立底色、右上角"复制 prompt"按钮，点击后按钮文字变为"已复制"并保持两秒。桌面端该块在滚动时保持可见。
- 页尾：在 GitHub 上编辑此条目、报告过期（链接到预填标题的 issue）、评估历史。

### 2.4 全局

- 顶部导航：首页、三个分类、搜索、GitHub 链接。
- 亮暗主题跟随系统，可手动切换。
- 移动端单列，prompt 块横向可滚动，页面不出现横向滚动条。

## 3. 文件清单

在 v2 目录结构之上新增：

```
_config.yml                 # 站点配置、排除规则、按路径给条目分配布局
_layouts/
  default.html              # 骨架：head、导航、页脚
  home.html                 # 首页
  category.html             # 分类页：怎么选 + 卡片列表 + 筛选
  entry.html                # 条目页：页头元数据 + 正文 + 复制按钮
_includes/
  entry-card.html           # 分类页与首页共用的卡片
  freshness.html            # 新鲜度徽标
assets/site/
  style.css                 # 唯一样式文件
  site.js                   # 复制、筛选、搜索、新鲜度计算、主题切换
index.md                    # 首页内容
search.json                 # Liquid 模板，构建时输出全部条目的索引
```

与既定结构的衔接：

- 分类目录的 `README.md` 加 frontmatter `permalink: /workflows/`。同一文件既是 GitHub 目录页的说明，也是站点的分类页，不另建 `index.md`。
- 条目文件不动，`_config.yml` 用 `defaults` 按路径为它们套用 `entry` 布局，条目中不写 `layout` 字段。
- `permalink: pretty`，条目地址为 `/workflows/tdd-superpowers/`。
- 排除 `docs/`、`bin/`、`assets/skills/`、`AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING.md`，它们不进入站点。`assets/skills/` 的 raw URL 由 GitHub 仓库提供，与 Pages 无关。

## 4. 关键实现点

**新鲜度徽标在客户端计算。** GitHub Pages 只在 push 时重新构建。若三个月无人提交，构建时算出的"新鲜"就是假的。`site.js` 读取页面上的 `evaluated_at` 现场计算：90 天内绿色，90 至 180 天黄色，超过 180 天红色并标注"需复核"。阈值与 `check-upstream.sh` 一致。

**复制的是原文而非渲染结果。** prompt 写在条目 md 的 fenced block 中，语言标记为 `prompt`。JS 找到对应的 `pre` 元素取 `textContent`，保证复制内容与 md 中逐字一致，不受样式影响。

**搜索不引入第三方库。** `search.json` 由 Liquid 在构建时遍历全部条目页生成，字段为名称、一句话、分类、来源、agent、正文前 200 字。`site.js` 做大小写不敏感的子串匹配，条目在百位以内足够。

**分类页的"怎么选"与卡片列表来自两处。** 前者是 `README.md` 正文，后者由 Liquid 用 `site.pages` 按 `category` 过滤生成。README 中不再手工维护条目表，v2 方案第 5 节"README 条目表由手工维护并由脚本校验"这一条取消。

**中文排版。** 字体栈以系统中文字体优先：PingFang SC、Hiragino Sans GB、Microsoft YaHei、Noto Sans CJK SC，不引入外部字体文件。正文字号不小于 16px，行高 1.7，段落宽度限制在 70 字符左右。

## 5. 设计方向

克制的编辑式版面，不用渐变英雄区与三栏特性网格。

- 三个分类各一个强调色，只用于卡片左侧细条、徽标与导航当前项，正文区域保持中性。
- prompt 块是每个条目页视觉最重的元素：深色底、浅色等宽字、明显的复制按钮。其余内容退后。
- 新鲜度徽标用色不用图标，色盲可辨：绿、琥珀、红并配文字。
- 暗色主题不是简单反色，重新定义背景层次与强调色明度。

## 6. 分阶段

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| 0 | 先完成 v2 迁移，至少六个条目落地 | 站点有真实内容可渲染 |
| 1 | `_config.yml`、三个布局、样式、条目页与复制按钮 | 任一条目页可访问，复制按钮拿到逐字 prompt |
| 2 | 分类页筛选、首页、搜索、新鲜度徽标 | 不看仓库目录即可从首页三步到达任意条目 |
| 3 | 暗色主题、移动端、报告过期链接、视觉打磨 | 手机上单列可读，无横向滚动 |

阶段 1 完成即可开启 GitHub Pages，后续阶段直接推送 main 生效。

## 7. 风险

| 风险 | 对策 |
|---|---|
| Jekyll 内置版本的 Liquid 缺少某个过滤器 | 只用 `where`、`where_exp`、`sort`、`date`，均为旧版本已有 |
| 条目 md 中的 prompt 含有 fenced block 嵌套 | 外层用四个反引号，v2 样例已如此书写；CONTRIBUTING 中明确要求 |
| 本地无 Ruby 无法预览 | 推到分支看 Pages 即可；需要本地预览时用 `docker run jekyll/jekyll` 一条命令 |
| 站点样式文件与 `assets/skills/` 同在 `assets/` 下 | 站点资源固定放在 `assets/site/`，互不干扰 |
