## 第一轮：拆机械结构

初稿用“第一层设计、第二个设计、第三个设计、最后一块”推进，像在念提纲。改成“先动的是 Session 的组织方式”“接下来是事件”“再往下是上下文”“最后是 Watchdog”，让段落靠内容转，而不是靠序号转。

同时删掉“这就是……”“这正是……”一类总结句，保留事实和判断。

## 第二轮：补证据和边界

补了三类硬信息：

- Ticket 的状态不跟 Executor Session 走，可以 handoff、resume、由多个 Executor 跑；Mandate 不可变，只有人的 stop 能撤回。
- outbox / effects 先落库再执行，外发消息有回执，同一个 id 不重复入队。
- 增加“文章和原型的距离”表，把 Router/Worker、Trigger/Thread、Inline/Spill、BYOM、Watchdog 分成“已落地 / 部分 / 方向”。

这一步是为了避免把二手解读写成一手事实。

## 第三轮：调节奏，去排比

初稿里“这是作者的经验值”重复了两次，改成一次；把“第二件事”“第三件事”改成更自然的过渡；把“不适合的场景也很明确”改成“以下场景不适合，或者成本不划算”。

删掉一段解释“为什么这很重要”的空话，让读者自己从机制里得出结论。

## 第四轮：收紧断言

给关键判断加限定：

- “DeepSeek Harness 团队文章里提出的 Super-Agent 架构”，不写成行业通称。
- Router 轻量、Worker 最强，明确标成“文章的建议，不是硬规则；原型里的模型可配置”。
- 适用场景加“按文章的描述”，不写成普适结论。
- 不适合场景补“单仓库、DeepSeek Harness 绑定”。
- 结尾补“Super-Agent 不是唯一解”，避免把一套架构写成唯一答案。

逐段读，改了这些：

- summary 从 64 字压到 59 字。

- “Mandate 是不可变的”补成“Mandate 是这次接单的授权凭据，不可变”，先定义再展开。
- “作者给了一个经验值……这是作者的经验值”删掉重复。
- 补两处站内链接：《主 Agent 不该是消息总线》《多 Agent 编排全景》，把这篇放回已有内容里。
- 图片 alt 文本改成描述图的内容，而不是重复标题。
