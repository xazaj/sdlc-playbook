# 文章润色记录：主 Agent 不该是消息总线

- 日期：2026-10-30
- 对象：`articles/local-multi-agent-coordination.md`
- 说明：按“去 AI 味”做了五轮，逐轮记录改了什么、为什么。本文不进入站点，只留过程。

## 第一轮：拆掉机械结构

初稿用“第一个洞、第二个洞、第三个洞、第四个洞”推进，读起来像 PPT。改成四个加粗的判断句，每段直接说结论：任务没有地方存、分派不可靠、没有隔离和验收、Token 模型相反。

同时删掉“把调度建在沙子上”这类比喻。它不增加信息，只增加腔调。换成一句直话：“消息没送到，任务就没派出。”

## 第二轮：补事实和定义

文章里出现了 L0/L1/L2、信封、Beads、Kanzo，但第一次出现时没有解释。补了三处：

- 明确 L0 是心跳和工具调用，L1 是完成/失败/重试，L2 是阻塞和需要决策；
- 明确信封里只有 summary、files、checks、risks 和 artifact 路径；
- 补 Beads 与 Kanzo 的区别：Beads 底层是 Dolt，管依赖和 claim；Kanzo 是 SQLite，管人看得见的卡片。

同时给 Beads、Kanzo、AgentBridge、Gas Town、Spec Kit、OpenSpec、Serena、ccusage 加了就地链接。

## 第三轮：调语气，补平衡

前两轮把 agentbus 的缺口写得很重，容易读成“这东西没用”。补了一段：它适合低频 L2、交叉 review、人给 agent 留一句话，不适合当任务总线。

把“第一层是通信、第二层是任务、第三层是执行”改成“通信层管……任务层管……执行层管……”，避免三段式排比。结尾原来连用三个“等……真的……”，改成三个短句，去掉朗诵感。

## 第四轮：收紧断言，补边界

把“600–900 行、2–3 天”改成“按我的估计”，避免把估算写成承诺。补了“即使有 prompt 缓存，这些内容仍然占上下文窗口”，防止读者把缓存当成免费。Gas Town 的依赖改成“原生安装依赖 tmux、Dolt 和 Go”，因为 Docker 路径不需要这些。

另外补了两个具体的省 token 做法：Beads 用 CLI 不挂 MCP，Kanzo 不挂主 Agent，由 daemon 自己连。

## 第五轮：读出声，修语病

最后一轮逐段读：

- “一个想被找到的 session”改成“一个希望被其他会话找到的 Claude Code 进程”；
- “四个人并行”改成“四个 worker 并行”，和后面的 worker 保持一致；
- “备选是 Gantry……以及 Trainmaster”改成“另外两个备选是 Gantry……；Trainmaster……”，避免“备选是”后面接两个东西；
- “一个 8 个任务的功能”改成“一个包含 8 个任务的功能”；
- “主 Agent 的 ingress”改成“主 Agent 的上下文入口”，少一个术语。

最后检查：全文只有一处“不是……而是……”，没有“首先/其次/最后”的机械过渡，没有“赋能/闭环/抓手/综上所述”这类词。
