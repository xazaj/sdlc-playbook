# 网站导航：AI 时代的工具与资源

- 日期：2026-10-30
- 状态：已落地
- 入口：https://aibrev.com/sdlc-playbook/sites/
- 首批：20 个站点，6 个分类
- 结论：值得有，但要做得窄。只记录“改变决策”的网站，不做通用 AI 目录。

## 为什么值得有

站点原有三类内容：`registry/` 是可安装的资产，`articles/` 是长文阅读，`projects/` 是仓库解剖。它们都回答“怎么做事”，但不回答“去哪里找现成的资源”。

AI 时代的工具和额度变化很快：某个模型这周免费、下周收费；某个 CLI 这周送额度、下周改规则。把这类信息记在文章里，三个月就过期；记在 registry 里，又会污染“可安装资产”的契约。单独做一个轻量导航，反而更合适。

## 分类设计

分类不是按“工具类型”硬切，而是按存量内容的使用场景切。现有文章和项目卡的标签集中在：`agentic-coding`、`verification`、`claude-code`、`harness`、`multi-agent`、`skills`、`ui-design`、`mcp`、`local-first`、`cost-optimization`。导航的六个分类就是这些标签的去重和归并。

| 分类 | 中文 | 数量 | 收什么 |
|---|---|---:|---|
| `agent-engineering` | 智能体工程 | 5 | agent harness、MCP、skills、多 agent 会话、prompt |
| `models-credits` | 模型与额度 | 5 | 模型数据库、API 路由、免费额度、订阅比价 |
| `local-infra` | 本地与部署 | 3 | 本地 runner、离线模型、自托管 |
| `design-frontend` | 设计与前端 | 3 | AI-native UI、agent UI 组件、设计约束 |
| `knowledge-research` | 知识与研究 | 2 | 官方工程博客、论文榜 |
| `productivity` | 效率工具 | 2 | 终端 agent 环境、语音输入 |

## 收录标准

一个网站要进来，至少满足三条：

1. **对应一个具体的 SDLC 决策。** 不是“AI 工具”，而是“选哪个模型 API”“这个订阅值不值”“有没有免费额度”“怎么让 agent 的界面不土”。
2. **有可核对的数据或持续更新。** 价格、额度、模型列表、限制条件，至少有一项是结构化、可验证的。
3. **不是另一个目录的搬运。** 如果它只是聚合别人的聚合，价值会快速衰减。

另外两条是硬约束：

- **标注利益关系。** 有 referral、affiliate、sponsor 的，必须写进 `caveats`；没有明确披露的，按“可能有”处理。
- **标注评估日期。** 任何条目都必须带 `evaluated_at`，超过 90 天标“待复核”，超过 180 天标“需复核”。

## 不收录

- 纯资讯站、纯新闻、纯观点：这些进 `articles/`，不进导航。
- 需要登录才能看主要内容、且没有公开说明的站。
- 只靠“AI 工具大全”堆量、没有方法论的站。
- 社交平台单帖、视频、PDF、课程页：它们不是“站点”，也不好复核。
- 代充、账号买卖、镜像站、非官方中转：不碰。
- 和 AI 无关的通用 UI、VPS、系统设计站：即使书签里有，也不进。

## 条目格式

```yaml
name: llm-perks
title: LLM Perks
url: https://llmperks.com/
summary: 免费 LLM API、免费软件、AI credits、订阅 ROI 和免费基础设施的实时目录。
category: models-credits   # SITE_CATEGORY_IDS 之一
tags: [llm-api, free-tier, pricing, credits]
stage: bootstrap           # 可选：bootstrap | define | design | build | verify
source: bookmark           # manual | bookmark | community
evaluated_at: 2026-10-30
status: active             # active | stale | dead
caveats:
  - 含 referral / affiliate 内容，引用前先看利益关系
  - 价格和额度以官方页面为准
featured: true
order: 10
```

正文三节缺一不可：`## 为什么收`、`## 什么时候用`、`## 注意`。构建时会校验，缺一节直接失败。

## 来源与取舍

- 16 个来自 Chrome 书签，优先取 2026 年 9–10 月新增的 AI 相关条目；4 个是手动补的官方文档/研究站。
- Safari 书签没有读取权限，本次未纳入。
- 书签里大量条目被跳过：X 单帖、YouTube、PDF、Google 搜索、登录后的 dashboard、代充/镜像/账号买卖、通用 UI 组件、VPS 和系统设计。它们不是“AI 时代好用的网站”，或者不适合公开推荐。
- `llmperks.com` 是这次新增书签里最直接的一个：首页标题写 “Free LLM APIs — models with free developer access — 276 models, November 2026”，页面标注 “updated 42 min ago”，维护的是活数据，不是静态榜单。它有 referral / affiliate 内容，条目里已经写进 `caveats`。

## 站点实现

- 内容目录：`sites/<name>.md`，与 `registry/`、`articles/`、`projects/` 平级。
- Schema：`site/src/content.config.ts` 的 `sites` collection；分类常量 `SITE_CATEGORY_IDS`。
- 正文契约：`site/src/lib/catalog.ts` 的 `assertSiteBodyContract`。
- 列表页：`/sites/`，按分类分组；标题直接外链，右侧“笔记”进站内详情。
- 详情页：`/sites/<name>/`，保留判断、使用场景、注意事项和外部链接。
- 导航：页头“网站”；全局搜索已把条目、文章、项目、网站放在同一个索引里。
- 外部链接全部 `target="_blank"` + `rel="noopener noreferrer"`。

## 维护

- 每次新增或复核都更新 `evaluated_at`；90 天进入“待复核”，180 天进入“需复核”。
- `status` 只有 `active` / `stale` / `dead` 三档，不用颜色单独表达。
- 价格、额度、referral 关系写进 `caveats`，不写进 summary。
- 站内不做筛选和分页。20 个条目按分类扫一遍就够；等超过 50 个再考虑。
- 不为导航写“详情长文”。它的价值是一句话判断加一个外链，不是再写一遍官网。
