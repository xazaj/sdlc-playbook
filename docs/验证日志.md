### 2026-09-03 确立编排层定位
调研本机现有资产后的三个发现，直接改变了实现：

1. **Claude Code 已有完整的资产登记机制** —— `known_marketplaces.json` 记来源 repo，`installed_plugins.json` 记 version / gitCommitSha / lastUpdated。gstack 也自带 `last-update-check` 与升级技能。**在本库复制一份版本号必然漂移成假数据**，因此登记卡只记"版本由谁管、去哪查"。
2. **登记卡不能放进 `catalog/skills/`** —— `install.sh` 会把那里的目录软链成真技能，登记卡的 description 会直接和上游原技能抢触发。已单开 `registry/`，纯文档，不挂载。
3. **vendored 暂不实现** —— 目前两个外部资产（superpowers、gstack）都有自己的分发与更新机制，没有落地到本库的理由。等真遇到散装资产（GitHub 上单个 SKILL.md、没有版本机制的）再做，届时约定放 `vendor/<name>/`。

版本检查用 `bin/check-update.sh`，路由技能在用法第 0 步调用：只在真正用到本库时检查，不装全局 hook，对其他项目零侵入。节流 4 小时。

- 摩擦点：目前没有 git remote，`check-update.sh` 走的是"无远端"分支。真正的检查逻辑（fetch + rev-list）尚未跑过，推远程仓库后要复验。**已于同日复验，见下。**
