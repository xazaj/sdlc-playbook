### 2026-09-03 确立编排层定位
调研本机现有资产后的三个发现，直接改变了实现：

1. **Claude Code 已有完整的资产登记机制。** `known_marketplaces.json` 记录来源仓库，`installed_plugins.json` 记录 version、gitCommitSha、lastUpdated。gstack 也自带 `last-update-check` 与升级技能。在本库复制一份版本号必然漂移为错误数据，因此登记卡只记录版本由谁管理、到哪里查询。
2. **登记卡不能放入 `catalog/skills/`。** `install.sh` 会把该目录软链为技能，登记卡的 description 会与上游技能争夺触发词。已单独建立 `registry/`，纯文档，不挂载。
3. **vendored 暂不实现。** 目前两个外部资产（superpowers、gstack）都有自己的分发与更新机制，没有落地到本库的理由。等遇到散装资产（GitHub 上单个 SKILL.md、没有版本机制）再做，届时约定放在 `vendor/<name>/`。

版本检查使用 `bin/check-update.sh`，由路由技能在用法第 0 步调用：只在真正用到本库时检查，不安装全局 hook，对其他项目无侵入。节流 4 小时。

- 摩擦点：当时没有 git remote，`check-update.sh` 走的是"无远端"分支。真正的检查逻辑（fetch 与 rev-list）尚未执行过，推送远程仓库后需复验。**已于同日复验，见下条。**
