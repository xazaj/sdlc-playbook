ste-zh 是一个约束 agent 汇报写法的技能：把航空与国防工业维护手册用的 ASD-STE100 受控语言原则，改写为中文规则。450 星，522 行 markdown，一个作者，建库三周。这张卡主张：它对 agent 汇报最大的贡献是一张状态词表，「已完成」不自动等于「已验证」，这一条就值回整份规则。

## 它解决什么问题

agent 的日常汇报有几种通病：叙述过程（我先看了……然后改了……）、用推测当结论（应该是并发导致的）、把没验证说成没问题（测试基本都过了）、把顺手做的私活藏进改动里（另外优化了一下日志）。这些写法在单轮对话里只是啰嗦，在多任务并行调度时是灾难：看板上几十张卡，每张卡的汇报读不出真实状态，人就得逐张追问。作者的另一个项目 Kander 是多 agent 看板调度器，这个技能就是为那个场景磨出来的。

## 怎么解的

[SKILL.md](https://github.com/dualface/ste-zh/blob/27d57e4d6609ce88e14dd15cbae355223a83b246/SKILL.md) 是 25 条规则加 5 个输出模板加自检清单。规则分四层：词（一词一义、先定义后使用、具体动词、名词串不超过 3 个）、句（一句一事、步骤句 30 字描述句 40 字、条件在前、主动语态）、段（一段一主题、步骤用祈使句、不写开放式列举）、汇报（关键信息先行、状态词固定、如实写验证、不编造）。术语、状态词、禁用近义词的权威定义在 [references/terminology.md](https://github.com/dualface/ste-zh/blob/27d57e4d6609ce88e14dd15cbae355223a83b246/references/terminology.md)。

[examples/result-report.md](https://github.com/dualface/ste-zh/blob/27d57e4d6609ce88e14dd15cbae355223a83b246/examples/result-report.md) 的结构值得单独说：先列「Agent 掌握的事实」八条，声明改写只改写法、不增加事实（R25），改写后的每个事实都来自这份清单；然后给改写前后对比，逐条标注违规规则编号。教学示例自己受控。

## 设计亮点

**状态词表是核心发明。** 工作状态只用 10 个词：已完成、部分完成、未开始、进行中、已验证、未验证、失败、跳过、阻塞、未确认。每个词三样东西齐备：权威定义、完成条件、禁用近义词（「搞定」「OK」「done」「基本完成」全部点名禁止）。四条配套规则连成一堵墙：「已完成」不自动表示「已验证」；已知失败不得写成「已完成，未验证」掩盖；必需检查未执行时不得宣称整项任务完成；来源没有检查记录时写「未确认」并附确认方法，不许用「可能」「大概」糊过去。

**规则可判定。** 25 条每条能机械检查：句长按汉字与英文单词各计 1 数出来，名词串数个数，一段数句数，情态词全文只剩「必须」「不得」「可以」三个且禁用近义词列表给出。自检清单把规则变成发出前的逐项核对，13 条通用项加按回复类型的专项检查。

**边界与优先级写死。** 只管 agent 写给用户的文字；代码、注释、commit message、写入项目的文件、原样引用的日志一律不管，引用必须一字不改。更高优先级指令和用户指定格式优先；输出语言切到英文时回到 STE 原味，步骤句不超过 20 个词、描述句不超过 25 个词。

**承认自己的失效模式。** [README](https://github.com/dualface/ste-zh/blob/27d57e4d6609ce88e14dd15cbae355223a83b246/README.md) 直说：本技能靠 agent 遵守上下文指令生效，没有程序强制；长会话与上下文压缩后会遗忘，风格退化就重发 `/ste` 恢复。不装成有强制力的工具，把补救动作也写清楚了。

**与标准的关系干净。** 不是 ASD-STE100 本身、不收录原文与受控词典、条目独立设计非直译、与 ASD 无隶属、权利声明给足、原版可在官网免费申请。借了五十年工业标准的信誉，边界画得比多数衍生项目认真。

## 借鉴清单

**能搬的：**

- 状态词表三件套写法：定义、完成条件、禁用近义词；工作状态与验证状态分离
- 情态词收敛到三个并给出禁用表与例外范围（「需要」表缺少义不受限）
- 可判定规则加发出前自检清单的结构，规则编号贯穿正文与示例
- 示例先列事实清单再改写、逐条标注违规：教学材料自身受控
- 失效模式的诚实声明：靠遵守不靠强制，退化怎么救写明白

**不适用的：**

- 没有校验器：25 条规则全靠模型自觉，长会话退化是结构性的，重发指令只是补救不是修复
- 对日常对话太重，适用面是任务汇报、排查结论与多任务总结，闲聊场景强套模板反而碍事
- 中文规则绑定了中文标点与混排细节，英文场景只剩句长与结构那几条还站着
- 三周九次提交的新仓库，规则未经大规模实测，禁用近义词表会有漏网
- 一词一义的前提是项目术语本身统一，存量术语混乱的仓库先用要付清这笔债
