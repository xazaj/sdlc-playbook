# 开局阶段：agent 常驻约定选型

## 要回答的问题

- 新项目或新仓库，要给 agent 立哪些常驻规矩？
- agent 产出的文字要不要立文风下限？
- 对外发表的文档要不要专门去 AI 味？
- 长任务放手执行前，自主性约束要不要装？

立规矩的时机不限于项目第一天：换模型、读者群变化、agent 行为出问题，都是回到本矩阵的信号。

## 判断依据

三个维度按权重排序：

1. **读者距离**：agent 的产出给谁读：只有自己、团队内部，还是项目外的人。读者越远，文字上规矩的回报越大；只有自己看的草稿，任何文字规矩都收不回成本。
2. **监督方式**：人会全程盯着（结对），还是长任务放手。决定自主性约束装不装。
3. **AI 指纹的代价**：产出被认出是 AI 写的，有没有实际损害：用户反感发版说明的营销腔，复盘失去可信度，技术文章被平台打标降权。

第一条权重最高。读者只有自己时，后两条再严重，也只需要轻的规矩。

## 选型矩阵

| 约定 | 适用条件 | 代价 | 反模式（不应使用的场合） |
|---|---|---|---|
| **不立（裸装）** | 一次性脚本；纯代码产出；机器读的结构化输出 | 无任何约束，输出质量全凭模型默认行为 | agent 会写给人读的文字的任何项目 |
| **文风与格式约束**（写进 AGENTS.md） | agent 会产出给人读的文字：文档、评审意见、提交信息、界面文案 | 一段常驻指令；针对特定模型版本写的补偿，换模型要复核 | 纯代码产出；机器读的输出 |
| **去 AI 味（sepia 技能）** | 对外发表、被认出 AI 会造成实际损害的文档：发版说明、公告、复盘、PR 回复、工单、技术文章 | 六个技能条目常驻，触发面宽，必须写边界；每篇多一道工序 | 日常对话、代码注释、内部工作笔记；小说路由混进工程仓库 |
| **英文轻量去 slop（no-ai-slop 技能）** | 英文一般文章：博客、营销文案、公告、随笔；草稿已在手上想磨尖去模式，或只要一份点名不改写的审计 | 单条目，比 sepia 轻；纯英文规则，对中文无效 | 工程域文档（走 sepia）与中文写作（走 sdlc-deai-zh）；重写级去味（走 humanizer）；与其他去味技能同装 |
| **英文整段重写去味（humanizer 技能）** | 英文一般文章要重写级去味：25 条 Wikipedia 来源模式按强度分级（前 5 条单次命中即改），可按声音样本对齐作者笔感，缺事实先问不编造 | 单条目；3.0 刚重构，行为随上游版本变化；触发面与其他去味技能重叠 | 中文与工程域文档（走 sdlc-deai-zh／sepia）；只要点名审计或轻磨（走 no-ai-slop）；与其他去味技能同装 |
| **中文白名单去 AI 味（sdlc-deai-zh，本库自建）** | 中文一般文章的成稿去味，且信息不许增减：按白名单触发标记逐句认，未命中规则的句子逐字保留 | 规则的频率数据自测且绑模型版本，换模型要复核；触发面与另两个去味技能重叠 | 英文文本与工程域文档（走 no-ai-slop／sepia）；与任一去味技能同装 |
| **自主执行约束**（写进 AGENTS.md） | 长任务放手执行，人不全程盯 | 含糊要求下发问变少，取舍要自测；换模型要复核 | 结对开发、每步都要人确认的场合；一次性小改动 |

四者可叠加，不互斥。每一条都等信号出现再装，不预支。

## 推荐路径

默认按读者距离决定：

- 纯代码产出、机器读的输出：不立文字规矩
- agent 会写给人读的文字：装文风与格式约束，这是下限
- 产出含对外发表的文档：再加 sepia。入口按动词选：新写用 write，只诊断用 review，最小改动用 refactor，全文重写才用 recreate
- 产出以英文一般文章为主：默认 humanizer（25 条模式整段重写，能给 2–3 段自己的文字做声音对齐最好）；只要点名不改写的审计或最轻的磨尖，改用 no-ai-slop 的 detect／edit。
- 产出以中文一般文章为主：改用本库自建的 sdlc-deai-zh（白名单式最小改写，信息不增不减）。去味技能仍然只装一个
- 存在长任务放手执行：加自主执行约束

出现以下信号时改变默认：

| 信号 | 改走 |
|---|---|
| 发版说明被嫌营销腔、复盘读着像模板、文章被平台打 AI 标 | 装 sepia，先拿一篇旧文跑 review 定位伤情 |
| 文字只是用力过猛、比喻连篇，读者并无「像 AI」的抱怨 | 文风约束那一半就够，不必上 sepia |
| 英文博客或文案被嫌 AI 腔 | 装 humanizer（单条目，模式分级整段重写）；只要审计不要改写，才用 no-ai-slop 的 detect |
| 中文文章被嫌 AI 腔，且这段文字的事实与信息不能动 | 用 sdlc-deai-zh 按触发标记逐句改，未命中规则的句子逐字保留 |
| agent 长任务中途停下问「要我继续吗」 | 装（或修）自主执行约束，而不是每次口头催 |
| 换了底层模型 | 文风与自主执行两条厂商约束回来复核，偏差方向可能翻转 |
| 仓库以结对为主 | 拆掉自主执行约束，它的前提在结对时是假的 |

## 交给 agent 执行时的差异

**约定必须落在文件里。** 口头立的规矩在上下文压缩后就丢了，AGENTS.md 是唯一不丢的载体。这与规格阶段的结论同源：文件是锚点，对话不是。

**下限与按需要分层。** 文风约束是常驻下限，每次产出都生效；sepia 是按需操作，只对要去味的文档走。两者不冲突也不互替：前者管「平时说话的腔调」，后者管「这篇要发表的文档的指纹」。砍掉下限只留 sepia，日常输出失控；只用下限不去味，发表文档带着指纹出门。

**agent 自查 AI 味有盲区。** 它对「自然」的标准与人不同，「读起来自然吗」式的自查不可靠。sepia 的 review 是按 rubric 的清单式诊断，输出具体条目而非印象，这部分可以交给 agent；「改完像不像人写的」的最终判断还是得人来。

**厂商约束的时效绑在模型版本上。** 文风与自主执行两条源自厂商针对特定版本的行为补偿，不是永恒正确的原则。换模型是复核信号，不能只看登记日期。

## 常见误判

- **把「文字难看」与「像 AI」混为一谈。** 前者是常驻文风约束的事，后者才需要 sepia。装错层的两个方向都亏：为每次输出去味太重，发表文档只调文风又不够。
- **让 sepia 对所有写作任务默认触发。** 上游触发描述覆盖一切写作，不写边界会与项目里其他写作类技能抢触发；内部工作笔记不需要去味。
- **去味技能装了不止一个。** sepia、no-ai-slop、humanizer 与 sdlc-deai-zh 的触发面都覆盖「让文字不那么像 AI」，同装会互相抢触发；按项目主流产出与语言选一个，边界写进 AGENTS.md。
- **结对仓库照抄自主执行约束。** 那段约束的前提是「用户没有实时观看」，结对时是假的；装了 agent 反而不问就动手。
- **装了厂商约束就再也不看。** 模型换代后偏差方向可能翻转，约束从有用变有害。
- **开局一次立十条规矩。** 约定越多相互打架的概率越大。只立当下有读者、有损害、有场景的那几条，出现信号再加。

## 落地资产

判定结果对应的执行资产，外部的登记在 `registry/`，本库自建的放在 `catalog/`：

| 判定 | 使用资产 | 登记卡 |
|---|---|---|
| agent 产出的文字要立文风下限 | 文风与格式约束（doc 卡，写进 AGENTS.md） | `registry/claude-prose-style.md` |
| 对外文档要去 AI 指纹 | sepia 的 write/review/refactor/recreate 入口 | `registry/sepia.md` |
| 英文一般文章去 slop 或模式审计 | no-ai-slop 的 edit/detect 入口 | `registry/no-ai-slop.md` |
| 英文一般文章整段去味重写 | humanizer 的重写入口 | `registry/humanizer.md` |
| 中文一般文章白名单去味 | sdlc-deai-zh 技能（本库自建，`install.sh` 直接挂载） | `registry/deai-zh.md` |
| 长任务自主执行 | 自主执行与交付范围约束（doc 卡，写进 AGENTS.md） | `registry/claude-autonomy-scope.md` |

外部资产本库不重复建设，只判断何时使用哪一个，安装方式与版本管理见各登记卡；本库自建资产由 `install.sh` 直接挂载，正文自包含，复制进任意 AI 聊天窗口即可使用。
